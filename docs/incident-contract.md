# S0 故障模型与数据契约

## 范围

模拟在线订单 API：`gateway` 调用 `order`，后者访问数据库或下游服务。数据只用于本地原型，不连接生产环境。所有时间戳为 ISO 8601 UTC；数值是合成值。

## 故障因果图与可观测信号

### 连接池耗尽

```text
数据库连接变慢或连接未及时归还
  -> order 可用连接耗尽
  -> 获取连接等待/超时
  -> order 延迟升高、5xx 增多
```

- 指标：`db_pool_in_use` 接近 `db_pool_limit`，`db_pool_wait_ms` 和 `order_request_duration_ms` 升高。
- 日志：`order` 记录连接获取超时；数据库健康信号仍正常。
- 追踪：慢 span 位于 `order -> database` 的连接获取或查询阶段。
- 部署：无相关变更是重要的排除线索，不单独证明根因。
- 易混淆项：数据库本身不可用、慢查询、下游等待导致线程占用。

### 部署后配置错误

```text
部署引入错误配置
  -> order 使用错误依赖地址或缺少必需配置
  -> 连接/初始化失败
  -> order 5xx 增多
```

- 指标：新版本错误率升高；旧版本基线正常。
- 日志：配置校验失败或连接目标不匹配。
- 追踪：失败集中于新部署版本，错误发生在依赖调用前或连接建立阶段。
- 部署：变更时间早于错误，且版本与失败请求对应。
- 易混淆项：部署期间的流量峰值、数据库短暂故障、单纯版本相关但无因果的共现。

### 下游超时

```text
下游服务响应变慢
  -> order 等待下游超过超时预算
  -> 请求耗时和 5xx 增多
```

- 指标：下游延迟和超时率升高；数据库连接池保持健康。
- 日志：`order` 报告下游请求超时；可能同时出现无关数据库告警文字。
- 追踪：慢 span 位于 `order -> downstream`，trace ID 能关联失败请求。
- 部署：没有对应变更时，部署假设应降低可信度。
- 易混淆项：连接池耗尽、部署变更、下游客户端本地排队。

### 证据不足

缺少能区分假设的信号，或关键来源不可用。此时真值为 `null`，不按猜测归类。不能把“没有观测到”当成“观测证明不存在”。

## 案例设计

固定 8 个 incident：`pool-01`、`pool-02`、`config-01`、`config-02`、`downstream-01`、`downstream-02` 六个可判定样本；`unknown-01`、`unknown-02` 两个证据不足样本。可判定样本每类两个不同时间和 trace ID 实例。

每个案例含告警时间窗、事件时间线，以及 metrics、logs、traces、deployments 四类记录。`unknown-01` 只有错误率升高和普通日志，缺少区分根因的追踪、部署和资源信号。`unknown-02` 有相互冲突的指标与不完整追踪，不能可靠确定根因。

## JSONL 数据契约

每行一个 JSON 对象：

- `incident_id`：稳定案例 ID。
- `service`：主要受影响服务。
- `window`：含 `start`、`end` 的 UTC 时间窗。
- `alert`：告警名称和观测值。
- `timeline`：按 UTC 时间排序的事件。
- `signals`：`metrics`、`logs`、`traces`、`deployments` 四类原始合成记录。
- 每条记录含 `record_id`、`timestamp`、`service` 和 `attributes`；日志另含 `message`。
- 根因标签不得写入 incident 行；它们保存在单独的 `data/labels.json`。

## 评测定义

按 incident 等权计数，报告分子、分母和样本数。证据不足样本在 Top1 分类准确率中单独报告，不混进三类故障准确率。

- **Top1 根因准确率**：在可判定样本中，第一根因与标签相同的样本数 / 可判定样本数；另报告证据不足判断的正确数 / 2。
- **证据有效率**：报告中存在且与该 incident 相符的证据引用数 / 报告引用总数。空引用时记为 0，并同时报告引用数。
- **错误行动建议率**：未经证据支持或标签规则判为危险的建议数 / 建议总数。S0 只有数据契约，暂不产生行动建议；零建议时指标记为“不适用”，不能记为 0%。
- **调查成本**：每例查询次数、累计延迟毫秒、输入/输出 token 数。S0 无查询和模型调用，记录为“不适用”；后续按逐例原始数据计算均值及样本数。

## 人工真值核对

不查看 `data/labels.json`，用 `data/incidents.jsonl` 核对 `pool-01` 的池使用率与连接等待，并核对 `config-01` 的部署版本、变更时间和配置错误日志。两例都有跨来源且时间顺序一致的证据。下游案例可通过 trace 的慢 span 与健康连接池区分；证据不足案例必须保留不确定。
